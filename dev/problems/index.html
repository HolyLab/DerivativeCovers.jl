Problem families

This companion package provides parameterized test problems with reference Hessians and Jacobians. Use them to measure cover tightness and to study how program structure affects it.

A generator returns a CoverProblem, which contains a function f, an evaluation point x0, and, when available, a closed-form reference Hessian from exact_hessian. Pass f and x0 to the usual cover functions, then compare the result with the reference:

julia> p = quadratic(6; rank=2, form=:factored);

julia> c = cover_hessian(p.f, p.x0);

julia> H = exact_hessian(p);

julia> all(abs.(H) .<= c.h_sum * c.h_sum')
true

julia> round(DerivativeCovers.cover_ratio(H, c.h_sum); digits=3)
0.879

The ratio never exceeds 1, and values closer to 1 indicate tighter covers. If n, rank, and the random seed are fixed, changing form represents the same quadratic with a different computational graph. Differences in the ratio therefore isolate the effect of graph structure:

julia> ratio(p) = round(DerivativeCovers.cover_ratio(exact_hessian(p), cover_hessian(p.f, p.x0).h_sum); digits=3);

julia> [ratio(quadratic(6; rank=2, form=form)) for form in (:entrywise, :matvec, :factored)]
3-element Vector{Float64}:
 0.051
 0.145
 0.879

The entrywise form sends all n^2 entries of A through separate nonlinear nodes that reconverge on the same inputs. The factored form instead uses one node for each of the rank layers, with no overlap. This reconvergence explains the difference in cover tightness.

DerivativeCoverProblems.DerivativeCoverProblems — Module
DerivativeCoverProblems

Parameterized families of scalar programs for studying cover quality.

The programs are written in generic Julia and depend on nothing here, so any operator-overloading tool can run them; DerivativeCovers tapes them by virtue of DerivativeCovers.TVar overloading the elementals they use.

Each generator returns a CoverProblem: a program f written from those elementals, the point x0 to evaluate it at, an optional idiomatic-Julia twin that computes the same function by an independent route, and an optional analytic hessian. The families differ in the property that drives cover looseness — how much the paths from an input to the output reconverge — and each has knobs for size, reconvergence, and dynamic range:

  • quadratic: x'Ax/2 with A = W*W' of prescribed rank, written entrywise, as a matrix-vector product, or in factored form. The same A in three programs, so the three differ only in graph structure.
  • deep_composition: layers of width channels around a shared trunk, so each layer fans a single node out to width consumers that immediately reconverge.
  • random_dag: a random program whose sharing parameter interpolates from a tree (sharing = 0) to heavy subexpression reuse (sharing = 1).

Wide dynamic range enters along two independent axes: sigma widens the log-magnitude spread of a family's coefficients, while rescale (with scales from logscales) spreads the units of the inputs.

DerivativeCoverProblems.CoverProblem — Type
CoverProblem

A scalar program together with the references needed to judge a cover of its Hessian.

  • name: a short identifier, unique within a family sweep.
  • f: the program. Built only from the elementals overloaded for DerivativeCovers.TVar, so f(x) records a tape when x is a vector of TVars, and evaluates normally on any other numeric vector (Float64, ForwardDiff.Dual, ...).
  • x0: the point at which the Hessian is covered.
  • twin: an idiomatic-Julia implementation of the same function, or nothing. It is written independently of f, by an independent route — array operations f cannot express (most families), or an explicit scalar loop when f is itself written in array notation (see mlp) — so agreement between the two is evidence that f is the function it claims to be.
  • hessian: x -> H, the analytic Hessian, or nothing when no closed form is available. Use exact_hessian rather than the field.

DerivativeCoverProblems.DagRecipe — Type

A random program, stored as the recipe that generated it: ops[k] builds node ninputs + k from earlier nodes, and the output is the sum of outputs. Replaying the recipe on a vector of any numeric type evaluates the same function, so one recipe serves the tape, the reference derivatives, and the plain evaluation.

DerivativeCoverProblems.JacobianProblem — Type
JacobianProblem

A vector-valued program together with the references needed to judge an asymmetric cover of its Jacobian — the vector-output counterpart of CoverProblem.

  • name: a short identifier, unique within a family sweep.
  • r: the program, mapping an input vector to an output vector. Built only from the elementals overloaded for DerivativeCovers.TVar, so r(x) records a tape when x is a vector of TVars and evaluates normally on any other numeric vector.
  • x0: the point at which the Jacobian is covered.
  • nout: the number of outputs of r.
  • twin: an independent idiomatic-Julia implementation of the same map, or nothing.
  • jacobian: x -> J, the analytic nout × n Jacobian, or nothing when no closed form is available. Use exact_jacobian rather than the field.

DerivativeCoverProblems.cancellation — Method
cancellation(n; m=n, delta=1e-3, aligned=false, support=1:n, sigma=0.0, rng=MersenneTwister(1)) -> CoverProblem

An adversarial pair of programs built from m quartets of squared linear forms whose signed sum cancels exactly, riding on a delta-weighted rank-1 quadratic:

acc = (delta/2) * (q'x)^2
for j in 1:m
    acc += 0.5*(a_j'xS)^2 + 0.5*(b_j'xS)^2 + s*(c_j'xS)^2 + s*(d_j'xS)^2
end

where xS = x[support], c_j = (a_j+b_j)/sqrt(2), d_j = (a_j-b_j)/sqrt(2), and a_j, b_j are drawn orthogonal to x0[support]. At s = -0.5 (aligned = false, the default) the rotation identity c_j c_j' + d_j d_j' = a_j a_j' + b_j b_j' makes every quartet's contribution to the Hessian cancel exactly; at s = 0.5 (aligned = true) the same identity makes it add. The two variants differ only in the sign of the two constants multiplying the c_j and d_j squares: every node of the tape up to that sign carries the same value in both, because every quartet linear form vanishes at x0 (orthogonality to x0[support]), so f, its gradient, and the magnitude of every elemental partial and adjoint coincide between the two variants — only the curvature they carry differs.

Closed forms (the Hessian is constant in x):

H_cancel  = delta * q*q'
H_aligned = delta * q*q' + sum_j 2*(a_j*a_j' + b_j*b_j')   (scattered onto `support`)

The minimal cover of H_cancel is hstar = sqrt(delta) .* abs.(q) = sqrt.(diag(H_cancel)) (a rank-1 |H|, since H_cancel is itself rank 1). The quadrature merge of the cancel variant attains sqrt.(diag(H_aligned)) exactly — the sign flip that cancels the Hessian does not touch the elementwise bound B, which sees only magnitudes — so its looseness against hstar is sqrt.(kappa) with kappa_i = diag(H_aligned)_i / diag(H_cancel)_i, the per-coordinate cancellation index.

m sets the number of quartets and hence the size of kappa on the support (more quartets, more cancellation, larger kappa); delta sets the scale of the surviving rank-1 term relative to the quartets; support restricts the quartets to a coordinate subset, leaving off-support coordinates untouched by any cancellation; sigma widens the log-magnitude spread of the quartet coefficients and of q. Two calls that agree in n, m, delta, support, sigma, and rng state draw the same x0, q, and quartets regardless of aligned, so a cancel/aligned pair built from fresh, identically seeded rngs shares every random draw and differs only in the program's two constants.

DerivativeCoverProblems.deep_composition — Method
deep_composition(n; depth=4, width=4, sigma=0.0, rng=MersenneTwister(1)) -> CoverProblem

A depth-depth composition of layers, each of which sums its width channels into a single trunk node and then feeds that node back into all width channels:

z = tanh.(W*x + b)
repeat depth times:
    t = sum(z)                       # one node, `width` consumers
    z = tanh.(a .* t .+ c .* z)
f = sum(z.^2) / 2

The trunk is the reconvergence: every channel of layer l+1 depends on every channel of layer l, so the paths from an input to the output multiply by width per layer. width and depth therefore tune reconvergence and program length independently of n.

sigma widens the input weights W and biases b only. The recurrent weights a and c keep unit scale (1/sqrt(width) per fan-in), because a wide spread there drives tanh into saturation and flattens the Hessian to nothing. Heterogeneous units belong on the inputs, which is where sigma puts them.

No closed-form Hessian; differentiate p.f.

DerivativeCoverProblems.families — Method
families(; sigma=0.0, seed=1) -> Vector{Pair{String,Any}}

The standard sweep: named generators n -> CoverProblem, one per family, differing in how severely the paths through the program reconverge. Pass the same n to each to compare families at fixed problem size, or sweep n within one to measure how a cover's looseness grows.

The three quadratic forms are seeded alike, so at a given n they carry the same Hessian and differ only as programs.

DerivativeCoverProblems.jacobian_cancellation — Method
jacobian_cancellation(n; nout=4, m=n, delta=1e-3, aligned=false, support=1:n, sigma=0.0,
                      rng=MersenneTwister(1)) -> JacobianProblem

An adversarial pair of vector-valued programs built from m quartets of linear forms whose signed sum cancels exactly, riding on a delta-weighted rank-1 Jacobian and fanned out to nout outputs:

T = sum_i [ 0.5*(a_i'xS) + 0.5*(b_i'xS) + s*(c_i'xS) + s*(d_i'xS) ]
r_k = delta * q[k] * (p'x) + q[k] * T

where xS = x[support] and c_i .+ d_i == a_i .+ b_i entrywise (an unequal split c_i = t_i .* (a_i .+ b_i), t_i entrywise in (0, 1), so all four forms are distinct and none is a scalar multiple of another). At s = -0.5 (aligned = false, the default) each quartet's contribution to every Jacobian entry cancels exactly; at s = 0.5 (aligned = true) it adds. The two variants differ only in the sign of the constant multiplying the c_i and d_i forms: every quartet form vanishes at x0 (orthogonality, arranged by the draw) and within each support column all four forms share one sign, so node values and the magnitude of every elemental partial coincide between the two variants — the surrogate Ũ and every merge built from it are identical, and only the signed Jacobian differs.

Closed forms (the Jacobian is constant in x; ghat = sum_i (a_i .+ b_i) scattered onto support, g = abs.(ghat)):

J_cancel  = delta .* q * p'
J_aligned = q * (delta .* p .+ ghat)'
Utilde    = abs.(q) * (delta .* abs.(p) .+ g)'     (both variants)

The sign alignment makes Utilde == abs.(J_aligned) exactly, and both Utilde and the two Jacobians are rank 1, so the minimal cover of each is exact and analytic. The per-entry cancellation index is constant across outputs: kappa_j = 1 + g_j / (delta * abs(p_j)) on the support, 1 off it — more quartets or smaller delta, larger kappa; support restricts the cancellation to a column subset, making the kappa profile anisotropic.

sigma widens the log-magnitude spread of the quartet coefficients and of the output scales q, whose spread sets the sum/max merge gap sum(abs, q)/maximum(abs, q) — the effective output multiplicity, nout at sigma = 0 and approaching 1 as one output dominates. Two calls that agree in everything but aligned share every random draw and differ only in the program's one constant.

DerivativeCoverProblems.mlp — Method
mlp(sizes; batch=4, sigma=0.0, activation=tanh, rng=MersenneTwister(1)) -> CoverProblem

The squared-error loss of a feedforward network, with the parameters as inputs. For sizes = (n0, n1, ..., nK), layer l = 1:K has a weight matrix W_l of size n_l x n_{l-1} and a bias vector b_l of length n_l, flattened (W1, b1, W2, b2, ..., WK, bK) into one vector of length p = sum_l n_l*(n_{l-1}+1):

z = data column                    # n0, fixed
for l = 1:K-1
    z = activation.(W_l*z .+ b_l)  # hidden layers
y = W_K*z .+ b_K                   # output layer, linear
f = sum_over_columns( sum(abs2, y - target) ) / 2

batch input/target column pairs are drawn once at construction and closed over; only the parameters vary thereafter. f is written in array notation: a matvec whose TVar factor meets a constant factor (the data column feeding layer 1, or feeding layer K directly when K = 1) records one linear tape node per row, while a matvec between two TVar factors (every hidden-to-hidden transition) records one inner-product node per row. Each column's error sums as one linear node, and the batch total sums as another, so the tape stays short despite the array notation.

twin computes the same loss by an explicit scalar loop: every row's dot product is the left-to-right chain w[1]*z[1] + w[2]*z[2] + ... in the order a dot node's parents follow, bias and activation are applied per scalar, and every sum (over output units, over the batch) is an explicit binary + chain. It therefore matches f node for node under a shared accumulation order, rather than taking an independent route through array operations as the other families' twins do.

sigma spreads the log-magnitude of the initial weights and biases, mirroring deep_composition's convention; the weights are additionally scaled by 1/sqrt(n_{l-1}) so a wider input layer does not by itself inflate the initial activations.

No closed-form Hessian; differentiate p.f.

DerivativeCoverProblems.quadratic — Method
quadratic(n; rank=n, form=:entrywise, sigma=0.0, rng=MersenneTwister(1)) -> CoverProblem

The quadratic f(x) = x'Ax/2 with A = W*W' positive semidefinite of the given rank, where W is n × rank and sigma sets the spread of its coefficients' log-magnitudes. The Hessian is A, independent of x.

form selects how the same function is written as a program, which is what the cover sees:

  • :entrywise — sum_{i,j} A[i,j] * x[i] * x[j] / 2. Every entry of A gets its own nonlinear node, and all n^2 of them reconverge on the inputs.
  • :matvec — y = A*x scalarized, then x'y/2. The n products x[i]*y[i] reconverge through the rows of A.
  • :factored — s = W'x, then sum(s.^2)/2. Only rank nonlinear nodes, each carrying a whole rank-1 layer of the Hessian, so no two nonlinear contributions overlap.

For rank = 1 the factored form's minimal cover is known exactly: H = w*w' forces h >= abs.(w), and abs.(w) = sqrt.(diag(A)) attains it.

Two calls that agree in n, rank, sigma, and rng state produce the same A and the same x0 in every form, so a comparison across forms isolates the effect of program structure.

DerivativeCoverProblems.random_dag — Method
random_dag(n; nops=4n, sharing=0.5, sigma=0.0, rng=MersenneTwister(1)) -> CoverProblem

A random program of n inputs and at most nops elementary operations, drawn from +, -, *, scaling, tanh, squaring, and sin. The output sums every node that no other node consumes, so every input reaches the output. At sharing = 0 generation also stops as soon as a single unconsumed node remains (once any curvature-carrying op has been drawn): the only way to grow a tree past that point is one long unary chain, whose accumulated derivative factors wander into under- or overflow. A draw whose ops all happen to be linear gets one final squaring node, so every generated program has a nonzero Hessian.

sharing controls subexpression reuse, and with it the reconvergence the cover has to contend with. Each operand is either an unconsumed node (probability 1 - sharing) or an arbitrary existing node (probability sharing). At sharing = 0 no node is ever consumed twice, so the program's graph is a tree: each input reaches each node along at most one path. At sharing = 1 operands are drawn from the whole program and paths reconverge freely. Reaching the output is graph reachability, not influence: with reuse, an input can enter only linearly (a zero Hessian row), or even through linear paths whose unit weights cancel exactly (a zero gradient entry as well). Both are rare, correct, and must be tolerated by downstream code.

A node whose magnitude at x0 leaves [1e-3, 1e3] is followed by a normalizing scale node, so * and ^2 chains can neither overflow nor collapse to a numerically zero derivative. A tanh input outside [-2, 2] is likewise normalized to magnitude 1 first: 1 - tanh(v)^2 underflows to exactly zero for large v, and a derivative-dead node erases its whole subtree from the gradient and the Hessian. These guards are what keep the program nonlinear at every length, and what make the recipe safe to replay at points other than x0.

No closed-form Hessian; differentiate p.f.

DerivativeCoverProblems.rescale — Method
rescale(p::CoverProblem, d::AbstractVector) -> CoverProblem

The same function in rescaled input coordinates: g(y) = f(y ./ d) at y0 = d .* x0, whose Hessian is Diagonal(inv.(d)) * H * Diagonal(inv.(d)).

This is the input-units axis of dynamic range, and it is exactly the transformation a scale-invariant cover must be covariant under: a cover h of p at x0 must reappear as h ./ d for the rescaled problem. Take d from logscales for a random spread.
