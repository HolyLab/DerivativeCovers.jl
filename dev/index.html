DerivativeCovers

DerivativeCovers.DerivativeCovers — Module
DerivativeCovers

Compute certified rank-1 bounds on Hessians and Jacobians without forming either matrix.

A Hessian cover is a nonnegative vector h satisfying abs(H[i,j]) <= h[i] * h[j] for every entry of H. cover_hessian records a scalar function on a Tape and computes such a cover, together with the gradient, in O(L) work for a tape of length L. The result is deterministic and certified.

A cover is covariant under rescaling: if x -> D*x, then h -> inv(D)*h; if f -> c*f, then h -> sqrt(c)*h. That holds exactly on any program whose blocks all split on parent values carrying a scale of their own. Where one does not, the split falls back on declared input scales and stays covariant when those are rescaled alongside, scales -> D*scales; guards_any_block says whether a given program is in that case.

using DerivativeCovers imports the main entry points and result types. Public utilities such as cover_ratio, tightness, and equilibrate are not exported; call them with the DerivativeCovers. prefix. The DerivativeCovers.Diagnostics submodule provides tools for studying how cover looseness affects downstream algorithms.

Installation

DerivativeCovers is not yet registered. Install it directly from its subdirectory in the repository:

using Pkg
Pkg.add(url="https://github.com/HolyLab/DerivativeCovers.jl", subdir="DerivativeCovers")

Quick start

Call cover_hessian with a scalar function and an evaluation point:

julia> f(x) = exp(x[1]) + sum(x[i] * x[i+1] for i in 1:length(x)-1);

julia> x0 = [0.5, -1.2, 0.3, 0.8];

julia> c = cover_hessian(f, x0);

julia> round.(c.h_sum; digits=4)
4-element Vector{Float64}:
 2.8332
 1.1455
 3.633
 0.6124

The result contains a nonnegative vector h such that abs(H[i,j]) <= h[i] * h[j] for every entry of the Hessian H. The Hessian itself is never formed. The same reverse sweep also computes the gradient:

julia> round.(c.grad; digits=4)
4-element Vector{Float64}:
  0.4487
  0.8
 -0.4
  0.3

This computation takes one forward pass and one paired reverse sweep: O(L) work for a tape of length L. Use cover_jacobian for vector-valued functions, cover_nls for nonlinear least-squares objectives, and cover_variance for the cheaper, uncertified variance estimate.

Using a cover

If h covers a Hessian H, then h[i] * h[j] bounds abs(H[i,j]), norm(h)^2 bounds the spectral radius, and h .* (h' * abs.(d)) bounds abs.(H * d). The package can also compute exact matrix-free products with hvp, jvp, and vjp, each in one additional sweep.

Two options control the result:

  • Cost versus tightness. cover_hybrid and cover_jacobian_hybrid divide contributions into G groups. Larger G usually gives a tighter cover and costs O(G * L).
  • How local covers are scaled. Some nodes admit a family of equally valid rank-1 covers, and split_block chooses among them from the magnitudes of the parent values. Where those carry no scale it falls back on declared input scales; the scales and ratio keywords are what state them. See Splitting a local cover.

Utilities such as cover_ratio, tightness, and equilibrate are public but not exported. Call them with the DerivativeCovers. prefix; see Quantities and extension points.

Studying a cover

Pass WithDiagnostics to cover_hessian to inspect the elementwise bound B and alternative merges:

julia> d = cover_hessian(WithDiagnostics(), f, x0);

julia> round(DerivativeCovers.cover_ratio(d.B, d.h_sum); digits=4)
0.4495

Diagnostics cost O(n * L) time and O(n^2) memory because they form an explicit matrix. They are therefore opt-in.

A cover loses tightness whenever absolute-value arithmetic prevents cancellation. This can happen in two channels: tangents carry an input's influence forward, while adjoints carry the output's sensitivity backward. cover_lattice computes covers for all four combinations of signed and absolute channels, making the cost of each choice visible for a given program:

julia> g(x) = (d = exp(x[1]) - 1 - x[1]; u = d * x[2]; exp(u) - u);

julia> lat = cover_lattice(g, [0.4, 1.5]);

julia> round.(lat.h_quad_signed ./ lat.h_quad; digits=3)   # what the tangent signs buy
2-element Vector{Float64}:
 0.222
 1.0

julia> round.(lat.h_quad ./ lat.h_quad_absadj; digits=3)   # what the adjoint signs buy
2-element Vector{Float64}:
 0.362
 0.364

Here d cancels along the two paths from x[1], and u reaches the output along paths with opposite adjoint signs, so both channels lose information.

The Diagnostics module can perturb a cover in controlled ways and measure the effect on downstream computations. The companion DerivativeCoverProblems package provides the Problem families used in these experiments.

Recording a program

DerivativeCovers.Tape — Type
Tape{T}

A Wengert tape recorded while a function runs on TVar inputs, holding its values and partials in the element type T. eltype(t) reports T: it is the working precision of the whole construction, and a value or weight a caller supplies is converted into it. Signed results such as gradients are returned in T; covers and other nonnegative bounds are computed and returned in magtype(T), which is T itself for a real floating-point type.

T may be a type whose values stand for sets of numbers, such as an interval type from IntervalArithmetic.jl. The values and partials recorded over a box then enclose those at every point of the box, magnitude takes the largest absolute value over each set, and the covers computed from the tape hold everywhere on the box. Program control flow that the set does not decide, such as a comparison between overlapping intervals, raises an error while recording.

The first ninputs nodes represent the function inputs. Later nodes are appended in topological order, so every parent precedes its child. Node k stores its value vals[k], parent indices parents[k], first partials ds[k][i] = ∂φ_k/∂v_{p_i}, and the second partials Cs[k], a Curvature holding the symmetric ∂²φ_k/∂v_{p_i}∂v_{p_j} in whatever form the elemental supplies: UnaryCurvature or BinaryCurvature for a unary or binary elemental, PairedCurvature for an inner-product node (see dotnode), DeclaredCurvature for a declared sub-map output (see submapnode), and NoCurvature for a node with no second-order term.

Input nodes and constant output nodes have no parents and no second partials.

DerivativeCovers.TVar — Type
TVar(t::Tape{T}, idx::Integer)
TVar(c::Real)
TVar{T}(c::Real)

A scalar used while recording a function, carrying a value of type T. The CoverVar backend that records onto a Tape.

TVar(t, idx) refers to node idx on t and takes the tape's element type. TVar(c) creates a constant with a value but no tape; this supports typed literals such as zero(eltype(x)) in generic numerical code, which reach TVar{T}(c) and so stay in the program's precision. Operations involving only constants are folded immediately. Operations that mix a constant and a recorded variable store the constant as a coefficient.

Propagating a cover forward

A cover can also be propagated forward without a tape. Each variable carries its value, its signed tangent, and a squared cover of its own Hessian; the last quantity directly gives the output's cover. Working memory is O(n) per live variable rather than per recorded operation, so the cost does not grow with the length of the program.

This reaches a specific corner of the sign lattice: every tangent sign is kept and every adjoint sign is discarded, because a forward pass cannot know how the output depends on its current variable. This corner is incomparable with the result from cover_hessian, which keeps adjoint signs and discards tangent signs. Which result is tighter depends on the program.

The channels are stored in whatever the starting point is made of. Pass a StaticVector and they become static too, so no operation allocates and the whole propagation costs a fixed amount of memory however long the program is; pass a Vector and each operation allocates its channels. The static form is for a handful of inputs, since it compiles for the exact input count.

DerivativeCovers.FVar — Type
FVar{T, S, M, SM}

A scalar of type T that propagates a Hessian cover forward. This is the tape-free CoverVar backend.

S and SM are the storage of the tangent and cover channels, and M = magtype(T) the type of the cover and of the declared scale (see ForwardContext). M and SM follow from T and S, so FVar{T, S} names the variable type as well. A constant carries the storage too, because generic numerical code builds typed literals from eltype, which is all it has to reach the backend by.

For each variable, the propagation holds the value, the signed tangent ∇v, a squared cover of ∇²v (see ForwardChannels), the scalar declared scale sigma the split falls back on, and whether ∇v is identically zero (see ForwardScale). Working memory is O(n) per live variable rather than per recorded node, so a program whose intermediates go out of scope costs O(n × live width) and never materializes a tape.

Build one with forward_cover rather than directly.

DerivativeCovers.forward_cover — Function
forward_cover(f, x0::AbstractVector; scales=nothing, ratio=nothing, check=true) -> ForwardCover
forward_cover(x::FVar) -> ForwardCover

Compute a certified rank-1 cover of a scalar function's Hessian by propagating it forward, in one pass and with no tape.

f must accept a vector of FVars and return one, using operations FVar supports. Per variable the propagation carries the value, the signed tangent ∇v, a squared cover of ∇²v, and the scalar declared scale sigma; the recursions are

∇v_k    = sum_i d_i * ∇v_i
sigma_k = sum_i magnitude(d_i) * sigma_i
G_k     = sum_i magnitude(d_i) * G_i + sum over atoms of (sum_{i in atom} rho_i * magnitude.(∇v_i))^2

with rho the same local cover a reverse sweep builds, except that the adjoint factor is 1: a forward pass cannot know how the output depends on the node it is at. The cover is sqrt.(G).

The gradient is in the element type T = float(eltype(x0)) and the cover in magtype(T). As for cover_hessian, x0 may be a box of intervals: the gradient then encloses the gradient over the box and the cover holds at every point of it.

The second form returns the cover of any variable reached along the way, the propagation having maintained the invariant at every one of them, not only at the output.

Computational cost and tightness

O(n*L) time for n inputs and L operations, and O(n) memory per live variable — no tape, and nothing proportional to the length of the program. Its main advantage is therefore the ability to process programs that are too long to record.

The channels are stored in whatever x0 is made of, so a StaticVector point propagates in static arrays and no node allocates at all. That is worth doing for a handful of inputs and not for many: the propagation is then compiled for the exact input count, which for large n costs more in compilation than it saves at run time. A Vector point propagates in Vectors and compiles once for every size.

Currently, the tape-based cover_hessian with SignedTangents is tighter, since it merges the same atoms weighted by exact adjoints rather than by the unsigned path sums a forward pass has to use.

The cover this reaches is exactly the signed-tangent, absolute-adjoint corner of cover_lattice — h_quad_forward — which is therefore what it is tested against. That corner is incomparable with the default h_quad: it keeps every tangent sign and discards every adjoint sign, so which is tighter is a property of the program.

scales and ratio govern the split exactly as in cover_hessian: the propagation carries both of the references split_block reads, so it splits by the same rule a tape does and its cover is comparable with the tape's coordinate by coordinate. See forward_scale. check=true verifies every local cover.

Examples

julia> f(x) = exp(x[1]) + x[1] * x[2]^2;

julia> c = forward_cover(f, [0.5, 2.0]);

julia> round.(c.grad; digits=4)
2-element Vector{Float64}:
 5.6487
 2.0

julia> H = [exp(0.5) 4.0; 4.0 1.0];   # the Hessian of f at [0.5, 2.0]

julia> all(abs.(H) .<= c.h_quad * c.h_quad')
true

Cover entry points

At the same O(n*L) cost, the tangent channel distinguishes the covers below. By default, cover_hessian merges an absolute-value bound on the tangents, allowing its sum merge to collapse into a single O(L) reverse sweep. SignedTangents instead gives the tightest cover the package computes. It is tighter than the default at every coordinate and discards only cancellation between elementals. Its cost is O(n*L) because taking magnitudes inside the merge leaves nothing for a reverse sweep to collapse.

DerivativeCovers.cover_hessian — Function
cover_hessian([mode], t::Tape, outidx::Integer; check=true, scales=nothing, ratio=nothing, channel=AbsoluteTangents())
cover_hessian([mode], f, x0::AbstractVector; check=true, scales=nothing, ratio=nothing, channel=AbsoluteTangents())

Compute a certified rank-1 cover of a scalar function's Hessian.

Pass either a tape and scalar output node, or a function and evaluation point. The default CoverOnly mode returns a HessianCover containing the gradient and the sum-merge cover. WithDiagnostics additionally computes an explicit elementwise bound and a tighter quadrature cover.

The scales keyword declares the input scales the split falls back on where a block's parent values carry none, and ratio the threshold at which it does so; see split_block and split_ratio. Neither affects validity, only which of the valid covers is chosen, and guards_any_block says whether a program consults them at all. check=true verifies the local covering conditions.

The channel keyword chooses which tangents the merges run over; see TangentChannel. The default AbsoluteTangents is what makes the O(L) sweep possible. SignedTangents keeps the tangent signs and gives the tightest cover available at O(n*L), tighter at every coordinate than the default; it is available under WithDiagnostics only.

Two merges are available:

  • sum merge, h_sum = sum_k s_k: the cross terms of (sum_k s_k)(sum_k s_k)' are nonnegative slack;
  • quadrature merge, h_quad[i] = sqrt(sum_atoms s_atom[i]^2): valid by Cauchy–Schwarz, and the minimal cover of the no-cancellation surrogate M = sum_atoms s_atom s_atom'. An atom (see atom_slots) is a whole node for unary and binary elementals and one parent pair for an inner-product node, so an inner-product node contributes q separate terms to the quadrature merge rather than one.

Both satisfy abs.(H) <= h * h'.

The gradient is in the tape's element type T and the covers in magtype(T). T may be a type whose values stand for sets, such as Interval{Float64} from IntervalArithmetic.jl: recording f over a box x0 = interval.(lo, hi) then gives covers (here Vector{Float64}) that hold at every point of the box, and a gradient whose entries enclose the gradient over the box. Control flow in f that the box does not decide, such as a comparison between overlapping intervals, raises an error, as does an elemental evaluated outside its domain somewhere on the box (see check_values).

CoverOnly()

This mode takes one forward pass and one reverse sweep, or O(L) time and memory. The reverse sweep carries the ordinary adjoint and the absolute cover channel together:

vbar[p_i] += d_i * vbar[k]                          # signed channel: reverse-mode AD
abar[p_i] += magnitude(d_i) * abar[k] + rho_k[i]    # absolute channel: the cover

with rho_k from local_cover_slots. Both channels of node k are final when the sweep reaches it: adjoint flow and theta seeds come only from k's consumers, which follow it on the tape and are processed first. That makes rho_k — which needs the finished vbar[k] — computable in place, and abar[1:ninputs] equal to abs_reverse(t, theta)[1:ninputs] up to roundoff.

A program that reaches the declared-scale fallback requires one additional forward sweep.

WithDiagnostics()

This mode returns a HessianDiagnostics and costs O(n * L) time and O(n^2) memory. With check=true, it also verifies that the diagnostic and fused computations agree — as an equality under AbsoluteTangents, where both routes compute the same merge, and as a domination under SignedTangents, where the absolute route bounds the signed one.

Examples

julia> f(x) = exp(x[1]) + x[1] * x[2]^2;

julia> c = cover_hessian(f, [0.5, 2.0]);

julia> round.(c.h_sum; digits=4)
2-element Vector{Float64}:
 4.1125
 2.4142

julia> round.(c.grad; digits=4)
2-element Vector{Float64}:
 5.6487
 2.0

julia> H = [exp(0.5) 4.0; 4.0 1.0];   # the Hessian of f at [0.5, 2.0]

julia> all(abs.(H) .<= c.h_sum * c.h_sum')
true

DerivativeCovers.cover_jacobian — Function
cover_jacobian([mode,] t::Tape, outidxs; start=:covariant, rounds=4, a=nothing, check=true)
cover_jacobian([mode,] r, x0::AbstractVector; ...)

Asymmetric rank-1 cover of a vector-valued function's Jacobian: weights with a[k] * b[j] >= abs(J[k,j]). Pass either a tape and its output nodes, or a function and an evaluation point.

a is chosen by the balancing construction: start is :covariant, whose products on the support transform exactly under a rescaling of the program's inputs, outputs and intermediates, or :equal, which is permutation equivariant instead; rounds alternation rounds then refine it, and rounds = nothing runs balance_cover's alternation to convergence instead. Passing a yourself fixes the weights and rules out start and rounds. a must be strictly positive on every output some input reaches and may be zero on the others, which then contribute to no merge.

Modes

  • CoverOnly() (the default) returns a JacobianCover from O(L) sweeps, never forming the surrogate. Checking a pair against the surrogate is what the other mode is for, so check has no effect here; a factor that vanishes on a row or column the program actually uses is an error either way.
  • WithDiagnostics() returns a JacobianDiagnostics: the same a and b_sum, plus the surrogate and the two tighter merges, at O(m * L). check then verifies b_max against the surrogate.

Examples

julia> r(x) = [x[1] * x[2], exp(x[1]) - x[3], x[2] + 2x[3]];

julia> jc = cover_jacobian(WithDiagnostics(), r, [0.5, 2.0, -1.0]; a = ones(3));

julia> round.(jc.b_max; digits=4)
3-element Vector{Float64}:
 2.0
 1.0
 2.0

julia> all(jc.b_max .<= jc.b_quad .<= jc.b_sum)
true

DerivativeCovers.cover_nls — Function
cover_nls([mode], r, x0; ngroups=nothing, check=true, scales=nothing, ratio=nothing)

Compute covers for the least-squares loss f(x) = ½∑ₖ rₖ(x)² at x0.

r must map a vector of TVars to a vector of residuals. The default CoverOnly mode returns an NLSCover holding a cover h of the full loss Hessian and a cover h_gn of the Gauss–Newton matrix JᵀJ. WithDiagnostics returns an NLSDiagnostics, which adds the absolute-sensitivity surrogate Utilde for a further O(m * L).

ngroups sets the number of residual channels G, and with it the entire cost of the CoverOnly mode: O(G * L) time and O(G * n) memory. The default nothing gives every residual a channel of its own (G = m), the tightest pair of covers available. A smaller positive integer spreads the residuals cyclically over G channels and sums their sensitivities within a channel before the quadrature merge; both covers remain valid and can only loosen.

scales and ratio govern the split, as in cover_hessian, and reach only the residual-curvature channel: the residual channels carry unit atoms, which admit no split, so neither h_gn nor Utilde depends on them. check=true verifies the local covering conditions, and under WithDiagnostics also verifies h_gn against Utilde.

Examples

julia> r(x) = [x[1] * x[2] - 1.0, exp(x[1]) - 2.0];

julia> nc = cover_nls(r, [0.5, 2.0]);

julia> round.(nc.h; digits=4)
2-element Vector{Float64}:
 2.7014
 0.5

julia> round.(nc.h_gn; digits=4)
2-element Vector{Float64}:
 2.592
 0.5

julia> all(nc.h_gn .<= nc.h)
true

DerivativeCovers.cover_hybrid — Function
cover_hybrid(t::Tape, outidx::Integer, ngroups::Integer; check::Bool=true, scales=nothing, ratio=nothing) -> h
cover_hybrid(t::Tape, outidx::Integer, groups::AbstractVector{<:Integer}; check::Bool=true, scales=nothing, ratio=nothing) -> h
cover_hybrid(f, x0::AbstractVector, spec; check::Bool=true, scales=nothing, ratio=nothing) -> h

Compute a Hessian cover by grouping cover contributions: contributions are summed within each group, then the group totals are combined in quadrature.

An integer ngroups groups the tape's cover atoms (see atom_slots), dealing them round-robin. ngroups=1 is the sum merge, and any ngroups at or above natoms(t) gives every atom a group of its own, which is exactly the quadrature merge h_quad of diagnostic cover_hessian. Because atoms rather than nodes are dealt, the whole range between the two merges stays reachable however the program was written: an elemental that carries several atoms — an inner product, a matrix-vector product — spreads them across groups like the scalar chain it stands for.

Alternatively, groups[k] assigns tape node k to a group, holding all of that node's atoms together; cyclic_partition and level_partition build such partitions.

Every grouping produces a valid cover, and one group is always the sum merge. The computation costs O(G * L) time and memory for G groups. scales and ratio govern the split, as in cover_hessian, and check=true verifies local covers.

Examples

The two endpoints, on a tape carrying three atoms:

julia> f(x) = exp(x[1]) + x[1] * x[2]^2;

julia> round.(cover_hybrid(f, [0.5, 2.0], 1); digits=4)   # one group: the sum merge
2-element Vector{Float64}:
 4.1125
 2.4142

julia> round.(cover_hybrid(f, [0.5, 2.0], 3); digits=4)   # a group per atom: the quadrature merge
2-element Vector{Float64}:
 3.1062
 1.7321

DerivativeCovers.cover_jacobian_hybrid — Function
cover_jacobian_hybrid(t::Tape, outidxs, groups::AbstractVector{<:Integer}; kwargs...) -> (; a, b)
cover_jacobian_hybrid(t::Tape, outidxs, ngroups::Integer; kwargs...) -> (; a, b)
cover_jacobian_hybrid(r, x0::AbstractVector, groups | ngroups; kwargs...) -> (; a, b)

Compute a Jacobian cover by grouping outputs.

groups[k] assigns output k to a group. Absolute sensitivities are summed within each group, then the group totals are combined with max. Alternatively, pass ngroups to assign outputs cyclically.

Every grouping is valid. One group reproduces b_sum; one group per output reproduces b_max. The cost is O(G * L) for G = maximum(groups), without forming the full surrogate.

The output weights are cover_jacobian's, chosen by the same keywords:

  • start: :covariant (the default) or :equal.
  • rounds: alternation rounds refining them, 4 by default.
  • a: fixed weights of your own instead, strictly positive on every output some input reaches and optionally zero on the others. It rules out start and rounds.
  • check = true: verify the returned b against the surrogate, at O(m * L).

Returns the weights used and the grouped merge for them: a[k] * b[j] >= abs(J[k,j]).

Examples

The two endpoints, on a program with three outputs:

julia> r(x) = [x[1] * x[2], exp(x[1]) - x[3], x[2] + 2x[3]];

julia> t, outidxs = tape_function(r, [0.5, 2.0, -1.0]);

julia> round.(cover_jacobian_hybrid(t, outidxs, 1; a = ones(3)).b; digits=4)   # one group: b_sum

 3.6487
 1.5
 3.0

julia> round.(cover_jacobian_hybrid(t, outidxs, 3; a = ones(3)).b; digits=4)   # per output: b_max

DerivativeCovers.cover_lattice — Function
cover_lattice(t::Tape, outidx::Integer; check::Bool=true, scales=nothing, ratio=nothing)
cover_lattice(f, x0::AbstractVector; check::Bool=true, scales=nothing, ratio=nothing)

Compute the same Hessian cover four ways, once for each combination of a signed or absolute tangent channel with a signed or absolute adjoint channel, and return them in a CoverLattice.

Each channel is a place where the construction may discard signs. The tangent channel is either the exact derivatives from tangents or their absolute-value bound from sensitivities; the adjoint channel is either abs.(vbar) from adjoints or the unsigned acheck = abs_reverse(t, e_outidx), whose entry acheck[k] sums prod(abs(∂φ/∂v)) over every path from k to the output and therefore satisfies acheck >= abs.(vbar).

An absolute channel bounds the exact one wherever it cancels, so replacing a signed channel by its absolute counterpart can only inflate the cover. That orders the corners: h_sum_signed and h_quad_signed are the smallest, h_sum_absadj and h_quad_absadj the largest, and the two mixed corners fall between them but are incomparable with each other. The ordering in the adjoint channel relies on the split scaling with the local matrix, which it does: both of its scale references are properties of the parent nodes, and the adjoint enters every entry of the block alike.

Cost is O(n * L) time and O(n^2) memory: two forward channels, two elementwise bounds, and four merges, each of that order. This is a diagnostic — it measures what each sign channel is worth on a given program, which the O(L) production sweeps cannot report.

scales and ratio govern the split, as in cover_hessian; check verifies the local covering conditions and that the forward and reverse sweeps agree on the gradient and on the sum merge.

Examples

julia> f(x) = (d = sin(x[1]) - x[1]; u = d * x[2]; exp(u) - u);

julia> lat = cover_lattice(f, [0.7, 1.3]);

julia> round.(lat.h_quad; digits=4)          # the corner `cover_hessian` computes
2-element Vector{Float64}:
 3.1673
 0.0768

julia> round.(lat.h_quad_signed; digits=4)   # keeping the tangent signs as well
2-element Vector{Float64}:
 0.4854
 0.0768

julia> all(lat.h_quad_signed .<= lat.h_quad)
true

Splitting a local cover

Some second-derivative blocks admit a family of covers, and the split selects one member from the ratio of two scale references. Parent values are the reference wherever they carry a scale, which keeps the cover exactly covariant under a rescaling of the inputs and costs nothing beyond what the sweep already reads. At the blocks where they carry none — a vanishing value meeting a degenerate feasible segment — no covariant local choice exists at all, and the declared input scales stand in.

Two keywords on every cover entry point state that fallback: scales, one strictly positive entry per input (nothing means unit scales, asserting that the inputs share units), and ratio, how lopsided a value pair must be before it counts as carrying no scale. Neither affects validity. guards_any_block answers whether a given program consults them at all — on one that does not, the cover is exactly covariant with scales held fixed and no extra sweep is run.

DerivativeCovers.split_block — Function
split_block(ratio, c11, c12, c22, s1::SplitScale, s2::SplitScale) -> (rho1, rho2)

The member of the block's cover family the split selects, from the two channels each slot carries.

Parent values fix the split covariantly and continuously except at blocks where a vanishing value meets a degenerate feasible segment, and there no covariant local choice exists at all: the equalizing point runs to an endpoint that is itself zero or infinite. So the values are read wherever they carry a usable scale and the declared input scales stand in wherever they do not, which keeps covariance where it is attainable and asks for units only where it is not. value_bounds_split is the test and ratio its threshold; see split_ratio.

The guard compares two differently scaled quantities and is therefore not itself invariant: a rescaling moves a block's value ratio, and one sitting near ratio can cross it. Nothing narrower is available — the one degeneracy test a rescaling leaves alone is an exactly vanishing pair, and a value exactly zero at one point is of order the displacement at a nearby one, so that test catches a block at one evaluation point and not at its neighbors.

Cost: the guard is three comparisons on values already recorded, and the declared scales are built by the first block that asks for them rather than in advance. A program whose blocks all keep a usable value pair therefore pays nothing for the fallback; one that reaches a guarded block pays one extra O(L) forward sweep, once. guards_any_block answers which case a tape is in without running a cover.

source
DerivativeCovers.split_ratio — Function
split_ratio(ratio, T::Type) -> r

The degeneracy threshold a cover over element type T runs at, from the ratio keyword its entry point was given, in M = magtype(T). nothing means sqrt(eps(M)).

ratio is how lopsided a value pair must be before value_bounds_split counts it as carrying no scale, and it must lie in [0, 1): at 1 every pair is condemned. It caps the split asymmetry the value channel can express, since a multiplication block aims at rho1 = sqrt(c12*z2/z1) and so at a ratio of sqrt(ratio) between the two references.

The default resolves against M rather than being stored as a constant because the quantity it bounds is representability. eps(M) is the floor below which one parent value is indistinguishable from zero at the scale of the other; sqrt(eps(M)) is the half-the-digits margin above that floor, capping the asymmetry at eps(M)^(-1/4). A constant chosen at one precision is silently wrong at another — 1e-8 sits below eps(Float32), which would collapse the guard to an exactly-vanishing test on a Float32 program, and that test does not survive an ordinary perturbation of the evaluation point.

DerivativeCovers.guards_any_block — Function
guards_any_block(t::Tape; ratio=nothing) -> Bool

Whether any block of t could reach the declared-scale fallback, decided by the same value_bounds_split test the split itself applies and under the same conditions in which cover_slots! consults a scale at all.

This is how a caller learns whether the unit-scale default is load-bearing for their program. On a tape that answers false the cover reads parent values everywhere, is exactly covariant under an input rescaling, and pays no extra sweep. On one that answers true the cover imports the units its inputs are expressed in at the blocks where no covariant local choice exists, and stays covariant only when the declared scales are rescaled alongside.

The test reads recorded values and second partials, never an adjoint and never a tangent. The adjoint scales a block's three entries together, so it changes neither the value ratio nor which diagonal entries are nonzero, except where it underflows one of them to zero. Reading it that way overcounts — a block whose adjoint vanishes contributes no cover term for the fallback to reach — and, in that underflow corner alone, can undercount. Ignoring tangents overcounts too: a block with a dead_slot is covered diagonally and never consults a scale at all.

So this predicts which programs will ask for the declared scales without running a cover; the covers themselves build those scales on demand and never call it, and they are the authority on what a given tape does.

DerivativeCovers.sensitivity_scales — Function
sensitivity_scales(w, t::Tape) -> sigma

One abs_forward sweep seeded with the declared input scales w, so sigma_j >= sum_a w[a] * abs(∂v_j/∂x_a) with equality when no path cancellation occurs. w = nothing means unit scales, which asserts that the inputs share units.

These are the references the split falls back on where a block's parent values carry no scale. They transform exactly as the values do under a rescaling of the intermediate variables, so the covariance argument of balanced_split applies to them unchanged; under an input rescaling x -> D*x the cover stays exactly covariant when the scales are rescaled alongside, w -> D*w.

Cost: one O(L) forward sweep, paid once per cover and only by a program that reaches the fallback.

DerivativeCovers.value_bounds_split — Function
value_bounds_split(c11, c12, c22, z1, z2, ratio) -> Bool

Whether the value pair (z1, z2) fixes the split of the block [c11 c12; c12 c22].

balanced_split aims at sqrt(c12*z2/z1) and clamps it to the feasible segment [sqrt(c11), c12/sqrt(c22)], so a pair carrying no scale is harmless wherever the endpoint it runs toward is positive and finite: the clamp supplies the answer, and both endpoints are covariant. What is left is the pair of cases where that endpoint is degenerate as well — c22 == 0 puts the upper endpoint at infinity, c11 == 0 puts the lower one at zero — together with two vanishing values, which leave the ratio z2/z1 undefined whatever the block. ratio is how lopsided a pair must be to count as carrying no scale.

DerivativeCovers.balanced_split — Function
balanced_split(c11, c12, c22, z1, z2) -> (rho1, rho2)

Rank-1 cover of an off-diagonal-active 2×2 block [c11 c12; c12 c22], which requires c12^2 > c11*c22 (see offdiag_active). Returns rho1 >= sqrt(c11) and rho2 >= sqrt(c22) with rho1*rho2 == c12: the cover is exactly tight on the off-diagonal, so no cover of the block is smaller in both entries.

Those constraints leave a one-parameter family. The scale references z1, z2 — one per parent, supplied by split_block: the parent value magnitudes wherever they carry a scale, the weighted absolute sensitivities where they do not — pick a member, giving rho_i the units of sqrt(f)/[v_{p_i}] and making the cover scale-covariant. The result is continuous in all five arguments except where a vanishing scale reference meets a degenerate block; see the extended help.

Extended help

The three constraints confine rho1 to the segment [sqrt(c11), c12/sqrt(c22)] — nonempty precisely because c12^2 > c11*c22 — and fix rho2 = c12/rho1. Every returned cover lies on this segment, which is what makes it entrywise unimprovable: a competitor smaller in both entries would have rho1*rho2 < c12.

The position along the segment is the point that equalizes the value-weighted scales, rho1*z1 == rho2*z2, clamped to the segment when that point falls outside. Covariance follows: under a rescaling v_i -> d_i*v_i of the intermediate variables, c_ij -> c_ij/(d_i*d_j) and z_i -> d_i*z_i, so both endpoints and the equalizing point scale as 1/d_1; clamp is positively homogeneous, so rho_1 -> rho_1/d_1 and rho_2 -> rho_2/d_2.

Clamping is also what keeps the result continuous as a parent value vanishes: the equalizing point runs off to an endpoint, and the endpoint absorbs it. Nothing computes those limits separately, because floating-point arithmetic already carries them. sqrt(c12*z2/z1) is Inf at z1 == 0 and 0 at z2 == 0, which clamp resolves to the upper and the lower endpoint; c12/sqrt(c22) is Inf at c22 == 0, placing the upper endpoint there. Only z1 == z2 == 0 leaves a NaN that no clamp resolves, and that is what reaches the fallback.

That reasoning needs the endpoint being approached to be a positive finite scale, and it is not when the corresponding diagonal entry vanishes: c22 == 0 puts the upper endpoint at infinity, c11 == 0 puts the lower endpoint at zero. Nor is there any limit to take when both values vanish at once, since the equalizing point then depends on the ratio z2/z1 alone. In those cases the geometric mean of the endpoints is used, which is covariant and permutation-equivariant.

So the result is continuous except at three families of inputs, where it is the ratio z2/z1 that carries the information and the ratio is unavailable:

  • z1 == 0 with c22 == 0,
  • z2 == 0 with c11 == 0,
  • z1 == z2 == 0, for any block.

A multiplication node with a vanishing operand has c11 == c22 == 0 and meets all three at once. Among the elementals of overloads.jl it is the only source of the first and third: c22 == 0 otherwise requires x^y at x == 1, and ^ rejects a nonpositive base, so it never presents a vanishing z1. The second is also reached by x^y at a zero exponent, where c11 == 0 and z2 == 0 while c22 > 0.

These zero-reference cases concern the value channel, and they are exactly the ones value_bounds_split detects: split_block substitutes the declared scales there, and a declared scale vanishes only at a slot with no tangent, which cover_slots! covers diagonally instead of splitting. So a split reaches this function with a pair that is not degenerate, and a pair carrying a ratio reaches the geometric mean only when c12*z2/z1 leaves the range of the element type at a block whose feasible segment has a degenerate endpoint. There the equalizing point is recomputed from the separated exponents, which represents it whenever it is representable at all; see split_fallback. A split that is genuinely out of range throws, since every pair returned here is a cover. Entries that are already non-finite are returned as IEEE arithmetic gives them, which is what check=false asks for.

DerivativeCovers.split_fallback — Function
split_fallback(lo, hi, c12, z1, z2) -> rho1

The equalizing point balanced_split aims at, for blocks where sqrt(c12*z2/z1) misses it.

A pair with a ratio to read misses it only by overflow or underflow of the product under the root, and frexp recovers the point from the separated exponents: the exponent arithmetic is exact, and a rescaling by powers of two shifts e by an even amount, so this form is covariant to the bit exactly as the product form is. Tangent channels

DerivativeCovers.TangentChannel — Type
TangentChannel

Which tangents a cover construction merges over: the exact ones, or an absolute-value bound on them. The built-in channels are AbsoluteTangents, the default, and SignedTangents. Pass one with the channel keyword to cover_hessian.

A channel defines tangent_channel. The choice affects tightness and cost, but not validity: every channel dominates abs.(∇v) entrywise, which is all the merges require.

source
DerivativeCovers.AbsoluteTangents — Type
AbsoluteTangents()

The TangentChannel that merges over sensitivities, the absolute-value bound utilde >= abs.(∇v). This is the default, and the only channel whose sum merge collapses into a single O(L) reverse sweep — the bound is linear in the seeds, so abs_reverse can carry the whole merge (see CoverOnly).

What it gives up is cancellation along the paths from an input to a node, which SignedTangents keeps.

source
DerivativeCovers.SignedTangents — Type
SignedTangents()

The TangentChannel that merges over abs.(∇v) from tangents, the exact gradient magnitudes.

Paired with the signed adjoints every cover already uses, this is the tightest cover of the O(n*L) tier: abs.(∇v) <= utilde entrywise, so it dominates the default channel at every coordinate, and the only cancellation it still discards is the cancellation between elementals, which the triangle inequality over nodes throws away before any channel is chosen.

It costs O(n*L) time and memory, and cannot be cheaper: the merge takes magnitudes of each tangent inside the sum, where nothing is linear in the seeds and no reverse sweep collapses it. So CoverOnly rejects this channel rather than quietly becoming O(n*L).

Matrix-free products

DerivativeCovers.hvp — Function
hvp(t::Tape, outidx::Integer, v::AbstractVector) -> Hv
hvp(f, x0::AbstractVector, v::AbstractVector) -> Hv
hvp!(Hv, t::Tape, outidx::Integer, v::AbstractVector) -> Hv

Hessian-vector product H*v of the taped program, formed without the Hessian by differentiating the adjoint recursion along v: one forward tangent sweep dv_k = sum_i (∂φ_k/∂v_i) dv_i seeded with v, then one reverse sweep carrying both the adjoints vbar and their tangents,

vbardot_i += (∂φ_k/∂v_i) * vbardot_k + vbar_k * sum_j (∂²φ_k/∂v_i∂v_j) * dv_j.

The curvature term of each node comes from curvature_apply!, which every Curvature supplies in the form its structure allows — a PairedCurvature node reads its 2q nonzeros off the pairs rather than scanning a 2q × 2q matrix, without which a program built from q-long inner products would cost O(q) gradients instead of two. A node whose second partials are only declared (has_exact_partials is false) makes an exact product impossible: hvp throws on any tape containing one, unconditionally, rather than letting success depend on whether the node's adjoint happens to vanish. The tape method of scaled_spectral_radius inherits this restriction; its dense method does not.

Costs about two gradients and O(L) memory.

hvp! writes into Hv, which shares the axes of v. It saves the result allocation only: the two sweeps still allocate their own O(L) working vectors, so it is not allocation-free.

Examples

julia> f(x) = exp(x[1]) + x[1] * x[2]^2;

julia> x0, v = [0.5, 2.0], [1.0, 0.0];

julia> round.(hvp(f, x0, v); digits=4)
2-element Vector{Float64}:
 1.6487
 4.0

julia> h = cover_hessian(f, x0).h_sum;   # the cover bounds the product

julia> all(abs.(hvp(f, x0, v)) .<= h .* (h' * abs.(v)))
true

jvp!(Jv, t::Tape, outidxs::AbstractVector{<:Integer}, v::AbstractVector) -> Jv

Jacobian-vector product J*v of the taped vector-valued program, formed without the Jacobian by a single forward tangent sweep dv_k = sum_i (∂φ_k/∂v_i) dv_i seeded with v at the input nodes and read off at outidxs. Costs one sweep and O(L) time and memory, independent of the output count m — unlike adjoints, which is O(m*L).

A repeated entry in outidxs yields an identical entry of Jv.

jvp! writes into Jv, which shares the axes of outidxs. It saves the result allocation only: the sweep still allocates its own O(L) working vector, so it is not allocation-free.

Examples

julia> r(x) = [x[1] * x[2], exp(x[1]) - x[3], x[2] + 2x[3]];

julia> round.(jvp(r, [0.5, 2.0, -1.0], [1.0, 0.0, 1.0]); digits=4)
3-element Vector{Float64}:
 2.0
 0.6487
 2.0

vjp(t::Tape, outidxs::AbstractVector{<:Integer}, u::AbstractVector) -> Jtu
vjp(r, x0::AbstractVector, u::AbstractVector) -> Jtu
vjp!(Jtu, t::Tape, outidxs::AbstractVector{<:Integer}, u::AbstractVector) -> Jtu

Vector-Jacobian product J'*u of the taped vector-valued program: one reverse adjoint sweep seeded with u[k] at node outidxs[k], read off at the input nodes. Costs one sweep and O(L) time and memory, independent of the output count m.

Outputs that name the same node accumulate their seeds, so a repeated entry in outidxs contributes the sum of the corresponding entries of u — the transpose of jvp's duplicated rows.

The seed u shares the axes of outidxs, the mirror of jvp's Jv.

vjp! writes into Jtu, which is indexed by the tape's inputs, Base.OneTo(t.ninputs). It saves the result allocation only: the sweep still allocates its own O(L) working vector, so it is not allocation-free.

Examples

julia> r(x) = [x[1] * x[2], exp(x[1]) - x[3], x[2] + 2x[3]];

julia> round.(vjp(r, [0.5, 2.0, -1.0], [1.0, 1.0, 1.0]); digits=4)
3-element Vector{Float64}:
 3.6487
 1.5
 1.0
