DerivativeCovers

DerivativeCovers.DerivativeCovers — Module
DerivativeCovers

Compute certified rank-1 bounds on Hessians and Jacobians without forming either matrix.

A Hessian cover is a nonnegative vector h satisfying abs(H[i,j]) <= h[i] * h[j] for every entry of H. cover_hessian records a scalar function on a Tape and computes such a cover, together with the gradient, in O(L) work for a tape of length L. The result is deterministic and certified.

The default ValueSplit rule is covariant under rescaling: if x -> D*x, then h -> inv(D)*h; if f -> c*f, then h -> sqrt(c)*h. SensitivitySplit has the same input covariance when its weights are rescaled as w -> D*w.

using DerivativeCovers imports the main entry points and result types. Public utilities such as cover_ratio, tightness, and equilibrate are not exported; call them with the DerivativeCovers. prefix. The DerivativeCovers.Diagnostics submodule provides tools for studying how cover looseness affects downstream algorithms.

Installation

DerivativeCovers is not yet registered. Install it directly from its subdirectory in the repository:

using Pkg
Pkg.add(url="https://github.com/HolyLab/DerivativeCovers.jl", subdir="DerivativeCovers")

Quick start

Call cover_hessian with a scalar function and an evaluation point:

julia> f(x) = exp(x[1]) + sum(x[i] * x[i+1] for i in 1:length(x)-1);

julia> x0 = [0.5, -1.2, 0.3, 0.8];

julia> c = cover_hessian(f, x0);

julia> round.(c.h_sum; digits=4)
4-element Vector{Float64}:
 2.8332
 1.1455
 3.633
 0.6124

The result contains a nonnegative vector h such that abs(H[i,j]) <= h[i] * h[j] for every entry of the Hessian H. The Hessian itself is never formed. The same reverse sweep also computes the gradient:

julia> round.(c.grad; digits=4)
4-element Vector{Float64}:
  0.4487
  0.8
 -0.4
  0.3

This computation takes one forward pass and one paired reverse sweep: O(L) work for a tape of length L. Use cover_jacobian for vector-valued functions, cover_nls for nonlinear least-squares objectives, and cover_variance for the cheaper, uncertified variance estimate.

Using a cover

If h covers a Hessian H, then h[i] * h[j] bounds abs(H[i,j]), norm(h)^2 bounds the spectral radius, and h .* (h' * abs.(d)) bounds abs.(H * d). The package can also compute exact matrix-free products with hvp, jvp, and vjp, each in one additional sweep.

Two options control the result:

  • Cost versus tightness. cover_hybrid and cover_jacobian_hybrid divide contributions into G groups. Larger G usually gives a tighter cover and costs O(G * L).
  • How local covers are scaled. Some nodes admit a family of equally valid rank-1 covers. A SplitRule chooses among them. ValueSplit, the default, uses the magnitudes of parent values; SensitivitySplit uses input-weighted sensitivities.

Utilities such as cover_ratio, tightness, and equilibrate are public but not exported. Call them with the DerivativeCovers. prefix; see Quantities and extension points.

Studying a cover

Pass WithDiagnostics to cover_hessian to inspect the elementwise bound B and alternative merges:

julia> d = cover_hessian(WithDiagnostics(), f, x0);

julia> round(DerivativeCovers.cover_ratio(d.B, d.h_sum); digits=4)
0.4495

Diagnostics cost O(n * L) time and O(n^2) memory because they form an explicit matrix. They are therefore opt-in.

A cover loses tightness whenever absolute-value arithmetic prevents cancellation. This can happen in two channels: tangents carry an input's influence forward, while adjoints carry the output's sensitivity backward. cover_lattice computes covers for all four combinations of signed and absolute channels, making the cost of each choice visible for a given program:

julia> g(x) = (d = exp(x[1]) - 1 - x[1]; u = d * x[2]; exp(u) - u);

julia> lat = cover_lattice(g, [0.4, 1.5]);

julia> round.(lat.h_quad_signed ./ lat.h_quad; digits=3)   # what the tangent signs buy
2-element Vector{Float64}:
 0.222
 1.0

julia> round.(lat.h_quad ./ lat.h_quad_absadj; digits=3)   # what the adjoint signs buy
2-element Vector{Float64}:
 0.362
 0.364

Here d cancels along the two paths from x[1], and u reaches the output along paths with opposite adjoint signs, so both channels lose information.

The Diagnostics module can perturb a cover in controlled ways and measure the effect on downstream computations. The companion DerivativeCoverProblems package provides the Problem families used in these experiments.

Recording a program

DerivativeCovers.Tape — Type
Tape{T}

A Wengert tape recorded while a function runs on TVar inputs, holding its values and partials in the element type T. eltype(t) reports T, and every cover computed from t returns it: T is the working precision of the whole construction, and a value or weight a caller supplies is converted into it.

The first ninputs nodes represent the function inputs. Later nodes are appended in topological order, so every parent precedes its child. Node k stores its value vals[k], parent indices parents[k], first partials ds[k][i] = ∂φ_k/∂v_{p_i}, and the second partials Cs[k], a Curvature holding the symmetric ∂²φ_k/∂v_{p_i}∂v_{p_j} in whatever form the elemental supplies: UnaryCurvature or BinaryCurvature for a unary or binary elemental, PairedCurvature for an inner-product node (see dotnode), DeclaredCurvature for a declared sub-map output (see submapnode), and NoCurvature for a node with no second-order term.

Input nodes and constant output nodes have no parents and no second partials.

source
DerivativeCovers.TVar — Type
TVar(t::Tape{T}, idx::Integer)
TVar(c::Real)
TVar{T}(c::Real)

A scalar used while recording a function, carrying a value of type T. The CoverVar backend that records onto a Tape.

TVar(t, idx) refers to node idx on t and takes the tape's element type. TVar(c) creates a constant with a value but no tape; this supports typed literals such as zero(eltype(x)) in generic numerical code, which reach TVar{T}(c) and so stay in the program's precision. Operations involving only constants are folded immediately. Operations that mix a constant and a recorded variable store the constant as a coefficient.

Examples

julia> t = Tape([0.5, 2.0]);

julia> DerivativeCovers.isconstant(x), DerivativeCovers.value(x)
(false, 0.5)

julia> c = TVar(3.0);   # a constant: a value and no tape

julia> DerivativeCovers.isconstant(c * TVar(4.0)), DerivativeCovers.value(c * TVar(4.0))
(true, 12.0)

Propagating a cover forward

A cover can also be propagated forward without a tape. Each variable carries its value, its signed tangent, and a squared cover of its own Hessian; the last quantity directly gives the output's cover. Working memory is O(n) per live variable rather than per recorded operation, so the cost does not grow with the length of the program.

This reaches a specific corner of the sign lattice: every tangent sign is kept and every adjoint sign is discarded, because a forward pass cannot know how the output depends on its current variable. This corner is incomparable with the result from cover_hessian, which keeps adjoint signs and discards tangent signs. Which result is tighter depends on the program.

The channels are stored in whatever the starting point is made of. Pass a StaticVector and they become static too, so no operation allocates and the whole propagation costs a fixed amount of memory however long the program is; pass a Vector and each operation allocates its channels. The static form is for a handful of inputs, since it compiles for the exact input count.

DerivativeCovers.FVar — Type
FVar{T, R, S}

A scalar of type T that propagates a Hessian cover forward. This is the tape-free CoverVar backend.

R is the active SplitRule type and S the channel storage (see ForwardContext). A constant carries both because generic numerical code builds typed literals from eltype, which is all it has to reach the backend by.

For each variable, the propagation holds the value, the signed tangent ∇v, and a squared cover of ∇²v; see ForwardChannels. Working memory is O(n) per live variable rather than per recorded node, so a program whose intermediates go out of scope costs O(n × live width) and never materializes a tape.

Build one with forward_cover rather than directly.

DerivativeCovers.forward_cover — Function
forward_cover(f, x0::AbstractVector; rule=VectorNormSplit(), check=true) -> ForwardCover
forward_cover(x::FVar) -> ForwardCover

Compute a certified rank-1 cover of a scalar function's Hessian by propagating it forward, in one pass and with no tape.

f must accept a vector of FVars and return one, using operations FVar supports. Per variable the propagation carries the value, the signed tangent ∇v, and a squared cover of ∇²v; the recursions are

∇v_k = sum_i d_i * ∇v_i
G_k  = sum_i abs(d_i) * G_i + sum over atoms of (sum_{i in atom} rho_i * abs.(∇v_i))^2

with rho the same local cover a reverse sweep builds, except that the adjoint factor is 1: a forward pass cannot know how the output depends on the node it is at. The cover is sqrt.(G).

The second form returns the cover of any variable reached along the way, the propagation having maintained the invariant at every one of them, not only at the output.

Computational cost and tightness

O(n*L) time for n inputs and L operations, and O(n) memory per live variable — no tape, and nothing proportional to the length of the program. Its main advantage is therefore the ability to process programs that are too long to record.

The channels are stored in whatever x0 is made of, so a StaticVector point propagates in static arrays and no node allocates at all. That is worth doing for a handful of inputs and not for many: the propagation is then compiled for the exact input count, which for large n costs more in compilation than it saves at run time. A Vector point propagates in Vectors and compiles once for every size.

Currently, the tape-based cover_hessian with SignedTangents is tighter, since it merges the same atoms weighted by exact adjoints rather than by the unsigned path sums a forward pass has to use.

The cover this reaches is exactly the signed-tangent, absolute-adjoint corner of cover_lattice — h_quad_forward — which is therefore what it is tested against. That corner is incomparable with the default h_quad: it keeps every tangent sign and discards every adjoint sign, so which is tighter is a property of the program.

rule selects the SplitRule, and only rules that reference something a forward pass carries are usable; see forward_scale. The default VectorNormSplit is the one whose scale reference — the tangent norm — the propagation already has, and it is the per-node minimizer of the quadrature merge this construction performs. check=true verifies every local cover.

That default differs from the tape entry points, which default to ValueSplit because a tape cannot afford a tangent norm. Two covers are comparable only under the same rule, so pass rule on both sides when comparing this against cover_hessian or cover_lattice.

Examples

julia> f(x) = exp(x[1]) + x[1] * x[2]^2;

julia> c = forward_cover(f, [0.5, 2.0]);

julia> round.(c.grad; digits=4)
2-element Vector{Float64}:
 5.6487
 2.0

julia> H = [exp(0.5) 4.0; 4.0 1.0];   # the Hessian of f at [0.5, 2.0]

julia> all(abs.(H) .<= c.h_quad * c.h_quad')
true

Cover entry points

At the same O(n*L) cost, the tangent channel distinguishes the covers below. By default, cover_hessian merges an absolute-value bound on the tangents, allowing its sum merge to collapse into a single O(L) reverse sweep. SignedTangents instead gives the tightest cover the package computes. It is tighter than the default at every coordinate and discards only cancellation between elementals. Its cost is O(n*L) because taking magnitudes inside the merge leaves nothing for a reverse sweep to collapse.

DerivativeCovers.cover_hessian — Function
cover_hessian([mode], t::Tape, outidx::Integer; check=true, rule=ValueSplit(), channel=AbsoluteTangents())
cover_hessian([mode], f, x0::AbstractVector; check=true, rule=ValueSplit(), channel=AbsoluteTangents())

Compute a certified rank-1 cover of a scalar function's Hessian.

Pass either a tape and scalar output node, or a function and evaluation point. The default CoverOnly mode returns a HessianCover containing the gradient and the sum-merge cover. WithDiagnostics additionally computes an explicit elementwise bound and a tighter quadrature cover.

The rule keyword chooses how local covers are scaled; see SplitRule. Every rule produces a valid cover. check=true verifies the local covering conditions.

The channel keyword chooses which tangents the merges run over; see TangentChannel. The default AbsoluteTangents is what makes the O(L) sweep possible. SignedTangents keeps the tangent signs and gives the tightest cover available at O(n*L), tighter at every coordinate than the default; it is available under WithDiagnostics only.

Two merges are available:

  • sum merge, h_sum = sum_k s_k: the cross terms of (sum_k s_k)(sum_k s_k)' are nonnegative slack;
  • quadrature merge, h_quad[i] = sqrt(sum_atoms s_atom[i]^2): valid by Cauchy–Schwarz, and the minimal cover of the no-cancellation surrogate M = sum_atoms s_atom s_atom'. An atom (see atom_slots) is a whole node for unary and binary elementals and one parent pair for an inner-product node, so an inner-product node contributes q separate terms to the quadrature merge rather than one.

Both satisfy abs.(H) <= h * h'.

CoverOnly()

This mode takes one forward pass and one reverse sweep, or O(L) time and memory. The reverse sweep carries the ordinary adjoint and the absolute cover channel together:

vbar[p_i] += d_i * vbar[k]                       # signed channel: reverse-mode AD
abar[p_i] += abs(d_i) * abar[k] + rho_k[i]       # absolute channel: the cover

with rho_k from local_cover_slots. Both channels of node k are final when the sweep reaches it: adjoint flow and theta seeds come only from k's consumers, which follow it on the tape and are processed first. That makes rho_k — which needs the finished vbar[k] — computable in place, and abar[1:ninputs] equal to abs_reverse(t, theta)[1:ninputs] up to roundoff.

SensitivitySplit requires one additional forward sweep.

WithDiagnostics()

This mode returns a HessianDiagnostics and costs O(n * L) time and O(n^2) memory. With check=true, it also verifies that the diagnostic and fused computations agree — as an equality under AbsoluteTangents, where both routes compute the same merge, and as a domination under SignedTangents, where the absolute route bounds the signed one.

Examples

julia> f(x) = exp(x[1]) + x[1] * x[2]^2;

julia> c = cover_hessian(f, [0.5, 2.0]);

julia> round.(c.h_sum; digits=4)
2-element Vector{Float64}:
 4.1125
 2.4142

julia> round.(c.grad; digits=4)
2-element Vector{Float64}:
 5.6487
 2.0

julia> H = [exp(0.5) 4.0; 4.0 1.0];   # the Hessian of f at [0.5, 2.0]

julia> all(abs.(H) .<= c.h_sum * c.h_sum')
true

cover_jacobian(t::Tape, outidxs::AbstractVector{<:Integer}; a=nothing, check=true) -> JacobianCover
cover_jacobian(r, x0::AbstractVector; a=nothing, check=true) -> JacobianCover

Compute asymmetric rank-1 covers of a vector-valued function's Jacobian.

Pass either a tape and output nodes, or a function and evaluation point. The result contains sum, quadrature, and max merges of the absolute sensitivities. For each returned b, a[k] * b[j] >= abs(J[k,j]).

DerivativeCovers.cover_nls — Function
cover_nls([mode], r, x0; ngroups=nothing, check=true, rule=ValueSplit())

Compute covers for the least-squares loss f(x) = ½∑ₖ rₖ(x)² at x0.

r must map a vector of TVars to a vector of residuals. The default CoverOnly mode returns an NLSCover holding a cover h of the full loss Hessian and a cover h_gn of the Gauss–Newton matrix JᵀJ. WithDiagnostics returns an NLSDiagnostics, which adds the absolute-sensitivity surrogate Utilde for a further O(m * L).

ngroups sets the number of residual channels G, and with it the entire cost of the CoverOnly mode: O(G * L) time and O(G * n) memory. The default nothing gives every residual a channel of its own (G = m), the tightest pair of covers available. A smaller positive integer spreads the residuals cyclically over G channels and sums their sensitivities within a channel before the quadrature merge; both covers remain valid and can only loosen.

rule selects the SplitRule for the residual-curvature channel. The residual channels carry unit atoms, which admit no split, so neither h_gn nor Utilde depends on it. check=true verifies the local covering conditions, and under WithDiagnostics also verifies h_gn against Utilde.

Examples

julia> r(x) = [x[1] * x[2] - 1.0, exp(x[1]) - 2.0];

julia> nc = cover_nls(r, [0.5, 2.0]);

julia> round.(nc.h; digits=4)
2-element Vector{Float64}:
 2.7014
 0.5

julia> round.(nc.h_gn; digits=4)
2-element Vector{Float64}:
 2.592
 0.5

julia> all(nc.h_gn .<= nc.h)
true

DerivativeCovers.cover_hybrid — Function
cover_hybrid(t::Tape, outidx::Integer, ngroups::Integer; check::Bool=true, rule=ValueSplit()) -> h
cover_hybrid(t::Tape, outidx::Integer, groups::AbstractVector{<:Integer}; check::Bool=true, rule=ValueSplit()) -> h
cover_hybrid(f, x0::AbstractVector, spec; check::Bool=true, rule=ValueSplit()) -> h

Compute a Hessian cover by grouping cover contributions: contributions are summed within each group, then the group totals are combined in quadrature.

An integer ngroups groups the tape's cover atoms (see atom_slots), dealing them round-robin. ngroups=1 is the sum merge, and any ngroups at or above natoms(t) gives every atom a group of its own, which is exactly the quadrature merge h_quad of diagnostic cover_hessian. Because atoms rather than nodes are dealt, the whole range between the two merges stays reachable however the program was written: an elemental that carries several atoms — an inner product, a matrix-vector product — spreads them across groups like the scalar chain it stands for.

Alternatively, groups[k] assigns tape node k to a group, holding all of that node's atoms together; cyclic_partition and level_partition build such partitions.

Every grouping produces a valid cover, and one group is always the sum merge. The computation costs O(G * L) time and memory for G groups. rule selects the SplitRule, and check=true verifies local covers.

Examples

The two endpoints, on a tape carrying three atoms:

julia> f(x) = exp(x[1]) + x[1] * x[2]^2;

julia> round.(cover_hybrid(f, [0.5, 2.0], 1); digits=4)   # one group: the sum merge
2-element Vector{Float64}:
 4.1125
 2.4142

julia> round.(cover_hybrid(f, [0.5, 2.0], 3); digits=4)   # a group per atom: the quadrature merge
2-element Vector{Float64}:
 3.1062
 1.7321

DerivativeCovers.cover_jacobian_hybrid — Function
cover_jacobian_hybrid(t::Tape, outidxs, groups::AbstractVector{<:Integer}; a=nothing, check=true) -> b
cover_jacobian_hybrid(t::Tape, outidxs, ngroups::Integer; a=nothing, check=true) -> b

Compute a Jacobian cover by grouping outputs.

groups[k] assigns output k to a group. Absolute sensitivities are summed within each group, then the group totals are combined with max. Alternatively, pass ngroups to assign outputs cyclically.

Every grouping is valid. One group reproduces b_sum; one group per output reproduces b_max. The cost is O(G * L) for G = maximum(groups), without forming the full surrogate.

a supplies the output weights and defaults to ones(m). check=true verifies the result against the surrogate.

DerivativeCovers.cover_lattice — Function
cover_lattice(t::Tape, outidx::Integer; check::Bool=true, rule=ValueSplit())
cover_lattice(f, x0::AbstractVector; check::Bool=true, rule=ValueSplit())

Compute the same Hessian cover four ways, once for each combination of a signed or absolute tangent channel with a signed or absolute adjoint channel, and return them in a CoverLattice.

Each channel is a place where the construction may discard signs. The tangent channel is either the exact derivatives from tangents or their absolute-value bound from sensitivities; the adjoint channel is either abs.(vbar) from adjoints or the unsigned acheck = abs_reverse(t, e_outidx), whose entry acheck[k] sums prod(abs(∂φ/∂v)) over every path from k to the output and therefore satisfies acheck >= abs.(vbar).

An absolute channel bounds the exact one wherever it cancels, so replacing a signed channel by its absolute counterpart can only inflate the cover. That orders the corners: h_sum_signed and h_quad_signed are the smallest, h_sum_absadj and h_quad_absadj the largest, and the two mixed corners fall between them but are incomparable with each other. The ordering in the adjoint channel relies on the split rule scaling with the local matrix, which ValueSplit and SensitivitySplit both do; a rule sensitive to the absolute scale of that matrix would still give covers, but not ordered ones.

Cost is O(n * L) time and O(n^2) memory: two forward channels, two elementwise bounds, and four merges, each of that order. This is a diagnostic — it measures what each sign channel is worth on a given program, which the O(L) production sweeps cannot report.

rule selects the SplitRule; check verifies the local covering conditions and that the forward and reverse sweeps agree on the gradient and on the sum merge.

Examples

julia> f(x) = (d = sin(x[1]) - x[1]; u = d * x[2]; exp(u) - u);

julia> lat = cover_lattice(f, [0.7, 1.3]);

julia> round.(lat.h_quad; digits=4)          # the corner `cover_hessian` computes
2-element Vector{Float64}:
 3.1673
 0.0768

julia> round.(lat.h_quad_signed; digits=4)   # keeping the tangent signs as well
2-element Vector{Float64}:
 0.4854
 0.0768

julia> all(lat.h_quad_signed .<= lat.h_quad)
true

The extended result returned by cover_hessian(WithDiagnostics(), ...), in the element type T of the Tape it was computed from.

  • grad: gradient of the scalar function.
  • B: explicit elementwise bound satisfying B >= abs.(H).
  • h_sum: cover computed with the sum merge.
  • h_quad: tighter cover computed by combining cover atoms in quadrature.
  • h_sum_rev: the absolute-value reverse sweep's own route to the sum merge, a consistency check.

B, h_sum and h_quad are formed over the TangentChannel the caller asked for, so under SignedTangents all three are the signed-tangent quantities. h_sum_rev is always the absolute-value route, which is what makes it independent; it equals h_sum in the default channel and dominates it in the signed one.

Forming these diagnostics costs O(n * L) time and O(n^2) memory.

DerivativeCovers.CoverLattice — Type
CoverLattice{T}

Covers of one Hessian computed with every combination of the two sign choices available to a cover construction, returned by cover_lattice.

Two channels feed the identity H = sum_k vbar_k * sum_{i,j in P_k} C^k[i,j] * ∇v_i (∇v_j)': the tangents ∇v_j, which carry an input's influence forward to each node, and the adjoints vbar_k, which carry the output's sensitivity back. Either can be propagated with signs or in absolute-value arithmetic. The absolute form is what a construction unable to see those signs must accept, and it costs tightness wherever the terms it merges would have cancelled.

tangent \ adjointsigned abs.(vbar)absolute acheck
absolute utildeh_sum, h_quadh_sum_absadj, h_quad_absadj
signed abs.(∇v)h_sum_signed, h_quad_signedh_sum_forward, h_quad_forward

All eight vectors satisfy abs.(H) <= h * h'. The absolute-tangent, signed-adjoint corner is what cover_hessian computes. The signed-tangent, absolute-adjoint corner keeps every sign a forward pass can see and discards exactly those only a reverse sweep supplies, so it is the cover a single tapeless forward propagation reaches.

  • grad: gradient, read off the signed forward sweep at the output node.
  • B, B_signed: elementwise bounds satisfying >= abs.(H), built from utilde and from abs.(∇v) respectively. B >= B_signed, and the gap is the path cancellation the absolute tangent channel discards.
  • h_sum, h_quad: sum and quadrature merges over the four channel pairings, named per the table above.

Forming these costs O(n * L) time and O(n^2) memory.

DerivativeCovers.JacobianCover — Type
JacobianCover{T}

Result of cover_jacobian, in the element type T of the Tape it was computed from. Each pair (a, b) satisfies a[k] * b[j] >= abs(J[k,j]).

  • a: output weights; ones(m) by default.
  • b_sum: sum merge, computed in one O(L) reverse sweep.
  • b_quad: the quadrature merge b_j = √(∑_k (Ũ_kj/a_k)²).
  • b_max: smallest valid b for the fixed a and the surrogate Utilde.
  • Utilde: m × n absolute-sensitivity surrogate satisfying Utilde >= abs.(J).
  • m, n: numbers of outputs and inputs.

The merges satisfy b_max <= b_quad <= b_sum coordinatewise.

DerivativeCovers.NLSCover — Type
NLSCover{T}

Result of cover_nls for the least-squares loss f = ½∑ₖ rₖ², in the element type T of the Tape it was computed from.

  • grad: gradient of the loss.
  • h: certified cover of the full Hessian JᵀJ + ∑ₖ rₖ ∇²rₖ.

Both covers are read off one grouped reverse sweep with G residual channels and one residual-curvature channel, so together they cost O(G * L) time and memory. With G = m — one residual per channel, the default — h_gn is the per-residual quadrature √(∑ₖ ũ²), which equals sqrt.(diag(J'J)) when no signed paths cancel.

DerivativeCovers.VarianceCover — Type
VarianceCover{T}

Result of cover_variance, in the element type T of the Tape it was computed from.

Split rules

Some second-derivative blocks admit a family of covers, and a rule selects one member. Two rules are exact optima: SensitivitySplit for the sum merge and VectorNormSplit for the quadrature merge. ValueSplit does not optimize either merge; it is the default because its scale reference is already available during cover computation.

DerivativeCovers.SplitRule — Type
SplitRule

Policy for choosing among the valid rank-1 covers of a single tape node.

Some 2×2 second-derivative blocks admit a one-parameter family of covers. A SplitRule supplies the scale used to choose one member of that family. The built-in rules are ValueSplit, the default, SensitivitySplit, which minimizes the sum merge, and VectorNormSplit, which minimizes the quadrature merge. Pass a rule with the rule keyword to cover functions. The choice can affect tightness, but not validity.

source
DerivativeCovers.ValueSplit — Type
ValueSplit()

Choose local covers using the magnitudes of their parent values. This is the default SplitRule.

The rule tries to equalize rho1 * abs(v₁) and rho2 * abs(v₂), subject to the feasible range. At nodes whose relevant parent values are zero, the cover remains valid but may vary discontinuously with the evaluation point. Use SensitivitySplit to avoid this value-based discontinuity.

source
DerivativeCovers.SensitivitySplit — Type
SensitivitySplit(w=nothing)

The SplitRule whose scale references are input-weighted absolute sensitivities: sigma_j is the abs_forward sweep seeded with the weights w at the inputs, so sigma_j >= sum_a w[a] * abs(∂v_j/∂x_a) with equality when no path cancellation occurs. w = nothing means unit weights; otherwise w must hold one strictly positive finite entry per input.

The split equalizes rho1*sigma_1 == rho2*sigma_2, clamped to the feasible segment. This is the exact minimizer of the weighted sum-merge objective sum_a w[a]*h_sum[a] over all per-node splits: the sum merge is linear in the per-node weights, so the objective decouples into one term rho1*sigma_1 + rho2*sigma_2 per node, minimized on the feasible segment by exactly this clamped equalization. w is therefore the statement of which cover the rule optimizes—the weighted sum of the input bounds—rather than a user-selected tuning parameter.

A zero scale is a certificate here, not a gap: sigma_j == 0 implies every path from the inputs to v_j carries a zero derivative product, so the total gradient of v_j vanishes identically and every Hessian contribution through that slot is exactly zero. Such a dead slot receives no cover weight and the surviving slot covers only its own diagonal; see local_cover_slots. This certificate is what requires w > 0: a zero weight could zero the scale of a live slot and mark it dead falsely.

Covariance: under a rescaling of the intermediate variables the sigmas transform exactly as the values do, so the covariance argument of balanced_split applies unchanged. Under an input rescaling x -> D*x the covers remain exactly covariant when the weights are rescaled alongside, w -> D*w; with w held fixed (the unit default included) the choice of split — never its validity — depends on the units the inputs are expressed in.

Cost: one extra O(L) forward sweep per cover.

source
DerivativeCovers.VectorNormSplit — Type
VectorNormSplit(w=nothing)

The SplitRule whose scale references are tangent norms: z_j = sqrt(sum_a w[a] * (∂v_j/∂x_a)^2), the w-weighted 2-norm of the signed tangent ∇v_j (see tangents). w = nothing means unit weights; otherwise w must hold one strictly positive finite entry per input.

The split equalizes rho1*z_1 == rho2*z_2, clamped to the feasible segment. This is the exact minimizer of the weighted quadrature objective sum_a w[a]*t[a]^2 over an atom's cover vector t = rho1*u_1 + rho2*u_2: with rho1*rho2 fixed by the block, the cross term is fixed too and rho1^2*z_1^2 + rho2^2*z_2^2 is smallest where the two agree. So this rule is to the quadrature merge what SensitivitySplit is to the sum merge, and w states which cover it optimizes rather than tuning anything. The downstream weight a node's atoms receive is a common factor and cannot affect the choice.

Two consequences distinguish it from the value-based default. A vanishing operand does not make the split singular: rho1*z_1 = sqrt(c12*z_1*z_2) vanishes continuously with either tangent, where ValueSplit has only the ratio of two zero values to go on. And a zero scale certifies nothing — a tangent can cancel to zero at a point without the gradient vanishing identically — so certifies_dead is false here, as it is for ValueSplit.

Covariance: under a rescaling of the intermediate variables the norms transform exactly as the values do, so the covariance argument of balanced_split applies unchanged. A norm mixes differently scaled input slots, so under an input rescaling x -> D*x the covers remain exactly covariant when the weights are rescaled as w -> D^2*w; with w held fixed (the unit default included) the choice of split — never its validity — depends on the units the inputs are expressed in.

Cost: the tangents themselves, O(n*L) time and memory for n inputs. This exceeds the O(L) cost of the other two rules because the scale reference uses whole vectors rather than one number per node. A forward propagation already carries the tangents and incurs no additional cost.

Tangent channels

DerivativeCovers.TangentChannel — Type
TangentChannel

Which tangents a cover construction merges over: the exact ones, or an absolute-value bound on them. The built-in channels are AbsoluteTangents, the default, and SignedTangents. Pass one with the channel keyword to cover_hessian.

A channel defines tangent_channel. The choice affects tightness and cost, but not validity: every channel dominates abs.(∇v) entrywise, which is all the merges require.

source
DerivativeCovers.AbsoluteTangents — Type
AbsoluteTangents()

The TangentChannel that merges over sensitivities, the absolute-value bound utilde >= abs.(∇v). This is the default, and the only channel whose sum merge collapses into a single O(L) reverse sweep — the bound is linear in the seeds, so abs_reverse can carry the whole merge (see CoverOnly).

What it gives up is cancellation along the paths from an input to a node, which SignedTangents keeps.

source
DerivativeCovers.SignedTangents — Type
SignedTangents()

The TangentChannel that merges over abs.(∇v) from tangents, the exact gradient magnitudes.

Paired with the signed adjoints every cover already uses, this is the tightest cover of the O(n*L) tier: abs.(∇v) <= utilde entrywise, so it dominates the default channel at every coordinate, and the only cancellation it still discards is the cancellation between elementals, which the triangle inequality over nodes throws away before any channel is chosen.

It costs O(n*L) time and memory, and cannot be cheaper: the merge takes magnitudes of each tangent inside the sum, where nothing is linear in the seeds and no reverse sweep collapses it. So CoverOnly rejects this channel rather than quietly becoming O(n*L).

source

Matrix-free products

DerivativeCovers.hvp — Function
hvp(t::Tape, outidx::Integer, v::AbstractVector) -> Hv
hvp(f, x0::AbstractVector, v::AbstractVector) -> Hv
hvp!(Hv, t::Tape, outidx::Integer, v::AbstractVector) -> Hv

Hessian-vector product H*v of the taped program, formed without the Hessian by differentiating the adjoint recursion along v: one forward tangent sweep dv_k = sum_i (∂φ_k/∂v_i) dv_i seeded with v, then one reverse sweep carrying both the adjoints vbar and their tangents,

vbardot_i += (∂φ_k/∂v_i) * vbardot_k + vbar_k * sum_j (∂²φ_k/∂v_i∂v_j) * dv_j.

The curvature term of each node comes from curvature_apply!, which every Curvature supplies in the form its structure allows — a PairedCurvature node reads its 2q nonzeros off the pairs rather than scanning a 2q × 2q matrix, without which a program built from q-long inner products would cost O(q) gradients instead of two. A node whose second partials are only declared (has_exact_partials is false) makes an exact product impossible: hvp throws on any tape containing one, unconditionally, rather than letting success depend on whether the node's adjoint happens to vanish. The tape method of scaled_spectral_radius inherits this restriction; its dense method does not.

Costs about two gradients and O(L) memory.

hvp! writes into Hv, which shares the axes of v. It saves the result allocation only: the two sweeps still allocate their own O(L) working vectors, so it is not allocation-free.

Examples

julia> f(x) = exp(x[1]) + x[1] * x[2]^2;

julia> x0, v = [0.5, 2.0], [1.0, 0.0];

julia> round.(hvp(f, x0, v); digits=4)
2-element Vector{Float64}:
 1.6487
 4.0

julia> h = cover_hessian(f, x0).h_sum;   # the cover bounds the product

julia> all(abs.(hvp(f, x0, v)) .<= h .* (h' * abs.(v)))
true
